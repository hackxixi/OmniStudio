# E1：JEV 编排 + 小模型填参数

背景与设计见 [product-direction.md §7 / §9.1](../../product-direction.md)。

## 文件

| 文件 | 内容 |
|---|---|
| `tasks.ts` | 8 个桩工具 + 26 个任务（L2 单步 18、L1 不该调工具 4、L3 两步 4）；桩结果里埋了只能从工具拿到的信息 |
| `bench.ts` | 四组：A 小模型原生工具调用 / B JEV 选步骤 + 小模型约束解码填参数 / B0 同 B 但不按附件过滤工具 / C 中等模型原生工具调用 |
| `verify.ts` | 事后用 JEV `noul` 给所有组的每条运行判「完成了没有」，与真值对照 |
| `results-r1.jsonl` | 第一轮原始结果（每行一条运行） |

在 ycs2 上跑（小模型容器 `~/jev/launch-e1-small.sh`，与 jev-sglang 共用 GPU4，**用完即停**——
它会吃掉 35B 的活动显存余量）：

```bash
cd /tmp/e1 && OUT=results.jsonl ~/.bun/bin/bun bench.ts A,B,B0,C
~/.bun/bin/bun verify.ts results.jsonl
```

## 第一轮（2026-09-24）

环境：小模型 = 魔搭 `Qwen/Qwen3.5-4B`（bf16，SGLang 0.5.19，关思考）；中等模型 =
`Qwen3.6-35B-A3B-AWQ`（同版本 SGLang，关思考）；JEV = OpenJev on 35B（`:18110`）。temperature 0，单次运行。

| 组 | 通过 | 工具选对 | 参数正确 | 平均耗时 |
|---|---|---|---|---|
| A 4B 原生 | **92%** (24/26) | 100% | 92% | 1059 ms |
| B JEV + 4B | 88% (23/26) | 100% | 88% | 1531 ms |
| B0 JEV + 4B（不过滤） | 88% (23/26) | 100% | 88% | 1428 ms |
| C 35B 原生 | **92%** (24/26) | 92% | 92% | 793 ms |

### 结论

1. **这套任务对 4B 太简单，分不出高下。** 4B 原生工具调用已经 92%，JEV 编排没有带来准确率提升，
   反而多了约 45% 的耗时（每步多一次 JEV 调用 + 一次独立的最终回答调用）。
   **不能据此说 JEV 编排没用，只能说 L2 单步 + 8 个工具不是它该发力的地方。**
2. **JEV 选步骤本身很稳**：52 次决策全部选对（含 L1 该直接回答的 4 题），最低置信度 0.595；
   这组任务里「只给可行选项」没有体现出差别（B 与 B0 结果相同），只是让两次决策的领先幅度变小。
3. **剩下的错误全在参数里，而且是推理型的**：「下周一」算成 10-05（三组共 3 次）、
   「截止日前一天」没减一天、「竖版 / 横版」对应不到尺寸枚举。这类错误 JEV 选步骤兜不住，
   要靠工具侧：日期参数给日历上下文或接受相对时间、枚举值写清楚含义（`1024x1792 = 竖版`）。
4. **35B 原生也会犯「小模型式」错误**：给「改写一句话」调了语音合成；
   发票任务只做了 OCR 却回答「已为您设置提醒」—— **声称做了没做的事**。
5. **JEV 当验收员有用，且与编排方式无关**（`verify.ts`，104 条运行）：

   | 阈值 | 抓到的失败 | 误报 |
   |---|---|---|
   | 0.80 | 4 / 10 | 0 / 94 |
   | 0.85 | 5 / 10 | 0 / 94 |
   | 0.90 | 7 / 10 | 4 / 94 |

   抓得住：发票提醒日期错（0.50）、横版画成方图（0.73～0.76）、35B 谎称已设提醒（0.82）。
   抓不住：「下周一」算错日期（0.95～0.96，要做日历推理）、不必要的语音合成（0.87）。

### 对方向的影响

- 「JEV 当**验收员**」比「JEV 当**调度员**」先有收益：它可以套在任何编排方式外面，
  0.85 阈值下零误报地拦下一半错误，正好接「逐级升级到云端」。
- 「JEV 当调度员」要在更难的条件下再测：见下一轮。

## 第二轮计划

把任务推到小模型会崩的区域，才能看出 JEV 调度有没有价值：

- **更小的模型**：魔搭 `Qwen3.5-2B` / `Qwen3.5-0.8B`（低端机器的真实情况），以及 4B 的 4bit 量化；
- **更多、更相近的工具**：25 个左右，含容易混淆的近义工具（知识库 / 笔记 / 记忆 / 网页搜索）；
- **更长的链**：L3 三到四步，步骤间有依赖；
- **该问用户的任务**：信息不足时应选「问用户」而不是瞎填；
- **工具侧修正**：日期给日历上下文、枚举写清含义，单独量出它能消掉多少参数错误。
